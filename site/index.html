Ship two subsystems at once with zero Git collisions.

          
Give each writer its own managed worktree and branch from your current dirty checkout. Verify independently, then preview and apply cleanly.

          $ claive open --engine codex --worktree --carry-dirty --alias core --prompt-file task.md
        

        
          
Make Claude critique Codex before you even read the diff.

          
Run bounded multi-round conversations across different model families. Every turn records a receipt, and peer replies never escalate permissions.

          $ claive conversation start @proposer @critic @reviewer --rounds 2 --message-file pr.md
        

        
          
Stop burning frontier quota reading 40 files.

          
Dispatch read-only Pi or AGY flash scouts to map unfamiliar code, then hand the tight brief to Codex or Claude Code for the final implementation.

          $ claive open --engine pi --model openrouter/flash --read-only --alias scout --prompt-file map.md
        

        
          
Queue goals on a server. Wake up to verified branches.

          
claive serve works a durable queue under systemd with wall-clock budgets, workspace allowlists, provider backoff, and parked-question inbox alerts.

          $ claive goal add --title "Audit deps" --workspace /abs/repo --budget 2h --prompt-file goal.md && claive serve

What to know before you run it on your repo.

    

      

        
Does it strip my agents' native tools or prompt cache?

        
Never. Codex, Claude Code, Pi, AGY, and Muse keep their native tools, MCP servers, Skillshare skills, repo instruction files, and provider caching.

      

      

        
What stops two agents clobbering my uncommitted edits?

        
--worktree --carry-dirty forks each writer into its own isolated Git worktree and branch. Changes merge back only after claive verify and apply --dry-run.

      

      

        
Which harnesses enforce read-only strictly?

        
Codex and Muse enforce read-only at the harness level. Claude Code, Pi, and AGY use soft-read instructions; pass --require-read-only when a hard write block is mandatory.

      

      

        
Does it need an account, API key, or cloud backend?

        
No. Claive is MIT licensed, Python 3 stdlib + Rust TUI, and runs 100% locally on Linux & WSL2 using the agent CLIs you already authenticate.

      

      

        
How does the Rust cockpit stay fast with live workers?

        
claive-tui uses Linux inotify, zero file locks, and a native incremental Rust events.jsonl tailer with automatic secret redaction.

      

      

        
Are there published benchmark win rates?

        
No. The earlier TTC benchmark study is intentionally deferred (docs/experiment/README.md). Claive ships deterministic isolation, triage, and test-gated rollback—never fabricated numbers.

      

    

  


  

    
Try it on one repo in 60 seconds.

    

      Clone, build the optional Rust cockpit, run claive doctor, and delegate your first isolated worker.
    


    

      
        

          
            
            
            
            
            
            
          
          
            
          
        


        
git clone https://github.com/ham-zax/claive.git && cd claive
just dash-build && ./install.sh --with-tui
claive doctor


        
claive open --detach --engine codex --worktree --carry-dirty \
  --alias backend --workspace /abs/repo --prompt-file /tmp/task.md

claive wait @backend && claive verify @backend && claive worktree apply @backend --dry-run


        
claive dash                    # read-only Rust cockpit (0 locks, native tailer)
claive dash --triage           # show only ASK / UNWATCHED / LOST / FAIL / REVIEW
claive dash --actions          # interactive answer / steer / verify / apply
CLAIVE_TMUX_TUI=1 claive-codex # 5-row compact tmux status pane


        
claive conversation start @proposer @critic @reviewer \
  --message-file /abs/design-question.md --rounds 2 --timeout 300


        
# Configure claive-mcp in Claude Code, Codex, or any stdio MCP host:
claive-mcp

# 10 flat-schema tools: claive_start · claive_peek · claive_steer · claive_wait
# claive_verify · claive_apply · claive_followup · claive_list · claive_cancel · claive_close


        
# Verifier-gated arbiter (L0 -> L1 refine -> L2 breadth):
claive-orch init --repo /abs/repo --task-file /abs/task.md --verify 'pytest -q' --arm D
claive-orch next RUN && claive-orch integrate RUN

# Unattended server queue (systemd/claive-serve.service):
claive goal add --title "Audit deps" --workspace /abs/repo --prompt-file /abs/goal.md && claive serve
